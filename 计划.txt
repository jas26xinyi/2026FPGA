# FPGA 密码锁与树莓派 5 报警拍照实施计划

## 1. 总体目标

- 目标 FPGA 为 HX7A75A / XC7A75T-FGG484-2，使用 Vivado 2023.2。
- 密码锁原有功能保持不变：默认密码 1234、管理员改密、确认/退格/取消、四次错误报警、KEY2 专用解除、8 秒输入超时、16 秒开锁超时、W25Q64 掉电保存和 KEY3 临时密码。
- OV5640 不再直接连接 FPGA。CSI 摄像头连接 Raspberry Pi 5，显示器也直接连接 Raspberry Pi 5 的 HDMI。
- 第四次密码错误时，FPGA 通过 3.3V TTL UART 通知 Raspberry Pi；树莓派连续拍摄四张完整图像，保存到本地，并以 2×2 四宫格持续显示。

## 2. 系统边界

```text
4x4 矩阵键盘 -> HX7A75A -> 数码管 / LED / 蜂鸣器
                         -> W25Q64 固定密码保存
                         -> UART ALARM 事件
                                      |
                                      v
CSI 摄像头 ---------> Raspberry Pi 5 ---------> HDMI 显示器
                              |
                              +---- 四张 JPEG + mosaic.jpg
```

- FPGA 不再生成摄像头 XCLK，不再执行 SCCB 初始化，不再接收 DVP 数据，也不再输出 TMDS。
- 原 OV5640、四帧 BRAM、视频时序和 rgb2dvi 源码及约束从 FPGA 工程删除。
- 树莓派负责相机初始化、四帧抓拍、文件保存、四宫格合成和 HDMI 全屏显示。
- FPGA 与树莓派之间不传输图像，只传输短控制消息，避免占用大量 FPGA 引脚和带宽。

## 3. FPGA 实现

- 顶层参数改为 `ENABLE_RPI_CAMERA`，默认值为 1。
- `ENABLE_RPI_CAMERA=1` 时加入 UART 报警通知模块；设为 0 时综合移除该模块，并让 TX 保持 UART 空闲高电平。
- 第四次错误进入 `ALAr` 时，现有 `capture_start` 单周期事件作为 `photo_trigger`。
- UART 固定为 115200 bit/s、8 数据位、无校验、1 停止位。
- FPGA 发送 ASCII 行 `ALARM\n`；树莓派收到后立即返回 `ACK\n`。
- 未收到 ACK 时 FPGA 每 500 ms 重发一次。拍照请求在 FPGA 内锁存，不因 KEY2 解除声光报警而取消。
- 树莓派完成或失败后分别发送 `DONE\n` 或 `ERR\n`；这两个状态用于日志，不改变密码锁、蜂鸣器或 LED 的既有行为。

## 4. 树莓派 5 实现

- 使用 Raspberry Pi OS Bookworm 或更新版本、Picamera2 和当前受支持的 libcamera/rpicam 相机栈。
- 相机主流配置为 RGB888、640×480，后台持续运行以减少报警后的首帧延迟。
- 收到 `ALARM` 后先回复 `ACK`，随后连续抓取四帧；四帧总耗时目标不超过 2 秒。
- 每次事件使用独立时间戳目录，先写入 `.partial` 临时目录；四张 JPEG 和 `mosaic.jpg` 全部成功后才原子改名为正式目录。
- 四宫格输出为 640×480，每张图位于 320×240 象限；显示窗口在树莓派 HDMI 上全屏显示。
- 首次拍照前显示测试色条；相机或抓拍失败时显示红色错误画面并返回 `ERR`。
- KEY2 只解除 FPGA 声光报警，不清除树莓派已保存的图像，最后一次四宫格保持显示直到下一次报警或程序退出。

## 5. 最优连接方案

采用板间 3.3V TTL 全双工 UART，使用 FPGA 上未接矩阵键盘的另一组 40 针 GPIO 扩展口：

| 方向 | FPGA 端 | FPGA 芯片脚 | 树莓派 5 端 |
|---|---|---|---|
| FPGA -> Pi | GPIOA_0，扩展口物理脚 1 | J16 | GPIO15/RXD0，物理脚 10 |
| Pi -> FPGA | GPIOA_1，扩展口物理脚 2 | H13 | GPIO14/TXD0，物理脚 8 |
| 公共地 | GND，建议扩展口物理脚 12 | - | GND，物理脚 6 |

- TX 与 RX 必须交叉连接，并连接公共地。
- 两块板均为 3.3V 逻辑，严禁把 5V 接到任何信号线。
- 两块板各自供电，不连接 3.3V 或 5V 电源脚。
- 线长建议小于 30 cm；若现场干扰较强，可将波特率降为 57600，但 FPGA 与配置文件必须同步修改。

## 6. 验证与验收

### FPGA

- UART 字节发送、接收、`ALARM` 帧、ACK 识别和 500 ms 重发通过 RTL 仿真。
- 原密码锁、临时密码、报警、矩阵键盘、数码管和 Flash 单元测试继续通过。
- 综合、实现、时序和 DRC 通过，并生成新的 `password_lock_top.bit`。

### Raspberry Pi

- 协议解析和四宫格顺序通过 Python 单元测试。
- `--mock-camera --trigger-on-start` 可在无 CSI 摄像头时生成四张模拟图并验证显示与存储。
- `rpicam-hello` 验证 CSI 摄像头后，使用真实 Picamera2 完成四帧抓拍。

### 联调

1. 树莓派程序显示测试色条并等待串口。
2. FPGA 连续输入四次错误密码，进入 `ALAr`。
3. 树莓派日志显示已回复 ACK，在 2 秒目标内保存四张照片并显示四宫格。
4. 按 KEY2 后 FPGA 声光报警解除，四宫格仍保留。
5. 再次触发报警，新四张照片进入新的时间戳目录并替换屏幕内容。

## 7. 验证边界

- FPGA 密码锁主体此前已完成实机验证。
